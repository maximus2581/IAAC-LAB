# Phase 3: Configuration Management (Ansible)

In the configuration phase, we use **Ansible** to perform baseline OS configuration and deploy our application roles across provisioned nodes.

The directory is structured to support multi-project inventories and modular playbooks:

```
ansible/
├── ansible.cfg                    # Configured for inventories/ and roles/
├── inventories/
│   ├── ceph.ini                   # Generated by terraform/projects/ceph
│   └── hitachi.ini                # Generated by terraform/projects/hitachi-lab
├── playbooks/
│   ├── base_provisioning.yml      # Hostname, /etc/hosts, baseline setup
│   ├── deploy_emulators.yml       # CCI + Hitachi Storage Emulators
│   └── deploy_sam4h.yml           # CCI + SAM4H Platform
└── roles/
    ├── cci/                       # Hitachi Command Control Interface
    ├── emulator/                  # Hitachi Storage Emulator (IntegSim)
    ├── sam4h/                     # SAM4H Container Platform
    └── ceph/                      # Ceph cluster configuration
```

---

## 🛠 Environment Setup (`uv`)

We utilize `uv` to maintain an isolated virtual environment for Ansible:

1. Navigate to the `ansible/` directory:
   ```bash
   cd ansible
   ```
2. Activate or execute commands through `uv`:
   ```bash
   uv run ansible --version
   ```

> 💡 **Tip for VS Code**: You can set your terminal to activate the `.venv` created by `uv` automatically (`source .venv/bin/activate`), eliminating the need to prepend `uv run` on every command.

---

## 🚀 Running Playbooks

Always specify the appropriate inventory file using the `-i` flag.

### 1. Test Connectivity
Verify that your provisioned VMs are reachable via SSH:
```bash
# For Ceph cluster nodes:
uv run ansible all -i inventories/ceph.ini -m ping

# For Hitachi lab nodes:
uv run ansible all -i inventories/hitachi.ini -m ping
```

### 2. Base Provisioning (Hostname & /etc/hosts)
Configures proper hostnames and local `/etc/hosts` resolution across all nodes in the target project:
```bash
# Apply to Ceph cluster:
uv run ansible-playbook -i inventories/ceph.ini playbooks/base_provisioning.yml

# Apply to Hitachi lab:
uv run ansible-playbook -i inventories/hitachi.ini playbooks/base_provisioning.yml
```

### 3. Deploy Project Workloads

#### Ceph Cluster:
Run your Ceph deployment playbooks or roles targeting `ceph_node` hosts:
```bash
uv run ansible-playbook -i inventories/ceph.ini <ceph-playbook>.yml
```

#### Hitachi Storage Emulators:
Requires manual placement of `HS042_122.iso` and `integsim-linux-*.tar.gz` in role `files/` folders (see below):
```bash
uv run ansible-playbook -i inventories/hitachi.ini playbooks/deploy_emulators.yml
```

#### Hitachi SAM4H:
Requires manual placement of `sam4hdockerinstaller-*.tgz` in `roles/sam4h/files/`:
```bash
uv run ansible-playbook -i inventories/hitachi.ini playbooks/deploy_sam4h.yml
```

## 🚫 Proprietary Binaries for Hitachi Lab
Due to licensing restrictions, Hitachi Vantara proprietary packages are not committed to Git. If deploying `hitachi-lab`, ensure the files are in place:
* **CCI**: `roles/cci/files/HS042_122.iso`
* **Emulator**: `roles/emulator/files/integsim-linux-10.5.3-00.tar.gz` and `install_sim.sh`
* **SAM4H**: `roles/sam4h/files/sam4hdockerinstaller-v2.4.2.tgz`
